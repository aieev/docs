배포 이후 문제가 발생한 경우, 아래 순서로 확인하세요.

## Runtime Logs 확인

배포 직후 문제가 발생한 경우 Runtime Logs를 먼저 확인하는 것이 가장 빠릅니다. 로그 화면에서 실시간 로그를 확인하거나 다운로드할 수 있습니다.

## 자주 확인할 항목

- 이미지 경로가 올바른지
- 비공개 레지스트리 인증 정보가 정확한지
- 포트 설정이 올바른지
- 시작 명령이 올바른지
- 헬스 체크 URL이 정상 응답하는지
- 환경 변수가 누락되지 않았는지

## 컨테이너 상태별 확인

### 대기중 상태

배포 직후 컨테이너가 **대기중** 상태인 경우에는 아직 실행 상태가 아닙니다.

<Note>
  대기중 상태에서는 과금이 발생하지 않으며, 실제 실행을 위해서는 **컨테이너 시작**이 필요합니다.
</Note>

### 배포 실패 상태

상태 옆의 **에러 상세** 칩을 열면 진단된 원인과 조치 방법을 확인할 수 있습니다. 전체 코드 목록은 [배포 오류 코드](/docs/ko/reference/error-codes)를 참고하세요. 창 안에서 런타임 로그로 바로 이동할 수도 있습니다.

주요 원인은 다음과 같습니다.

- 이미지 경로 오류
- 레지스트리 인증 실패
- 시작 명령 오류
- 요청한 자원이 장비 한도를 초과

배포 실패 상태에서는 과금이 발생하지 않습니다.

### 비정상 상태

컨테이너는 실행 중이지만 헬스 체크에 실패한 상태입니다. 이 상태에서도 **에러 상세**를 확인할 수 있습니다.

주요 원인은 다음과 같습니다.

- 애플리케이션 시작 실패
- 포트 설정 오류
- 헬스 체크 설정 오류 — 모델 로딩이 오래 걸린다면 헬스 체크 대기 시간을 늘리세요

비정상 상태에서는 과금이 발생하지 않습니다.

## 컨테이너가 시작되지 않을 때

컨테이너가 **대기중**에 머물거나 배포가 오래 걸린다면 해당 GPU에 여유 자원이 없을 수 있습니다. GPU의 가용성 표시를 확인하고 [GPU 가용성과 한도](/docs/ko/reference/gpu-availability-and-limits)를 참고하세요. 대기 신청을 하거나 다른 GPU를 선택할 수 있습니다.

## 설정 변경

대부분의 설정은 컨테이너를 정지한 뒤 변경할 수 있습니다. 컨테이너 이름, 레플리카 수, 영구 볼륨 용량은 실행 중에도 변경할 수 있습니다.
