AirCloud provides monitoring at two levels: **Project Monitoring** and **Container Monitoring**.

## Project Monitoring

From the Project sidebar, open **Monitoring** to view metrics for all containers within the Project.

If the Project contains multiple containers, their metrics are displayed together on the same chart with separate legends for comparison.

![Project Monitoring Eng942](/images/project-monitoring-eng942.png)

### Filters and Display Options

| Option | Description |
| --- | --- |
| **Container** | Display metrics for a specific container only. |
| **Metric** | Select the metrics to display. |
| **Project / Container** | Switch between aggregated project metrics and per-container metrics. |
| **Date Range** | Select the time range to view. |
| **Time Interval** | Choose the aggregation interval (for example, **1 minute** or **5 minutes**). |
| **Auto Refresh** | Enable or disable automatic updates. |

## Container Monitoring

From an individual container page, open **Monitoring** to view detailed metrics for that container.

Use the metric selector in the upper-right corner to customize the dashboard and display only the metrics you need.

![Runtime Endpoint Eng](/images/runtime-endpoint-eng.png)

### Available Metrics

| Metric | Description |
| --- | --- |
| **GPU Memory Usage** | GPU VRAM usage (MiB). |
| **GPU Utilization** | GPU utilization (%). |
| **CPU Utilization** | CPU utilization (%). |
| **Memory Usage** | System memory usage (GB). |
| **Network Traffic** | Total inbound and outbound network traffic (GB). |
| **Network Throughput** | Real-time network throughput (KB/s). |
| **Healthy Replicas Count** | Number of currently running Replicas. |
| **HTTP Requests per Second (QPS)** | Number of HTTP requests processed per second. |
| **HTTP P90 Latency** | 90th percentile HTTP response latency. |
| **HTTP Errors per Second** | Number of HTTP error responses per second. |
| **Request Count** | Number of requests over time. |
| **Total Requests** | Cumulative request count. |

### Replica Timeline

The **Healthy Replicas Count** card at the top of the container's monitoring page shows when Autoscaling added or removed Replicas, alongside your other metrics.

![Replica Timeline Eng](/images/replica-timeline-eng.png)

- **Replica count and runtime**: The line shows how the Replica count changed over the selected range, and the rows below it show when each Replica was running. Hover a bar to see the Replica ID and when it started and stopped.
- **Slots**: Each row is a slot, not a single Replica. When a Replica stops and another starts, the new one takes over the free row, so the number of rows matches the most Replicas that ran at the same time, however many were created. A row used by only one Replica is labeled with its ID; a row shared by several is labeled **Slot N**, and **×N** at the right shows how many Replicas used it. If there are more than 8 slots, click **Show N more slots** to see the rest.
- **Summary**: The line above the rows shows how many Replicas ran in the range, how many are still running or have terminated, and the median lifetime of the terminated ones.
- **Short-lived Replicas**: A Replica that ran only briefly appears as a dot. Dots that sit close together are grouped into a striped band.
- **Min and max guides**: The Autoscaling minimum and maximum Replica counts are drawn as dashed lines, so you can see how close you are to the limit. If Autoscaling is off, the card shows the fixed Replica count instead.
- **How Replicas are scaled**: Hover the ⓘ icon on the card to see the scaling rule. With Autoscaling on, a Replica is added when each Replica is handling more than the target number of concurrent requests on average, and removed when the load drops. With Autoscaling off, a change in the Replica count may mean a restart or a failure.
- **Scale markers**: Every metric chart marks the moments the Replica count changed with a vertical dashed line, so you can compare how requests, latency, GPU utilization, and other metrics changed before and after each scale event.

<Note>
  Autoscaling decides only from the number of concurrent requests per Replica. The scale markers help you compare metrics before and after a scale event; they do not mean that the metric on that chart caused it.
</Note>

#### Expanding a band

Click a striped band to list the Replicas grouped in it.

![Replica Timeline Band Eng](/images/replica-timeline-band-eng.png)

- The header shows the band's time range, how many Replicas it holds, and their median lifetime.
- Each row shows a Replica's ID, start and end time, and lifetime. Hover a row to mark that Replica on the band.
- Click **Zoom into this range** to narrow every chart on the page to the band, with a little margin on each side. Click **Reset zoom** to go back.

#### Replica list

Click **List** at the upper right of the rows (outlined in red below) to open a table of every Replica in the range, with its status, start and end time, and lifetime. Once the table is open, the button reads **Hide list**; click it again to close the table.

![Replica Timeline List Eng](/images/replica-timeline-list-eng.png)

- Search by Replica ID, and sort by **Most recent** or **Longest lived**.
- The table shows 10 Replicas per page. Use the arrows at the bottom right to move between pages.
- Hover a row to highlight that Replica in the timeline above. This is the easiest way to tell apart the Replicas that shared a slot (a row marked **×N**).

### Drag to Zoom

Drag across any chart to zoom every chart on the page into that range. The data is re-queried at a finer interval for the zoomed range. Click **Reset zoom** to return to the previous range.

## Container Runtime Logs

From the **Runtime Logs** page of a container, you can view logs for both running and terminated Replicas.

![Runtime Log Eng](/images/runtime-log-eng.png)

The left panel lists the Replicas, each marked **running** or **stopped**, with when it started and stopped. Select one to display its logs.

| Filter | Description |
| --- | --- |
| **Replica Search** | Quickly find a specific Replica. |
| **Time Range** | Display logs within a specific time range. The view starts from the last **7 days**. |
| **Keyword Search** | Search log contents using plain text or regular expressions. |
| **Log Level** | Filter by Debug, Info, Warning, or Error. |
| **Log Source** | Filter by standard output (`stdout`) or standard error (`stderr`). |
| **View Options** | Show timestamps, show raw data, hide health-check lines, and toggle word wrap. |

- Logs from both **running** and **stopped** Replicas remain viewable.
- **Jump to latest** returns to the newest lines after scrolling back.
- **Download** saves the selected Replica's logs, and **Download all** saves every Replica's logs at once.

<Note>
  If a deployment fails or behaves unexpectedly, checking the runtime logs is usually the fastest way to identify the cause. Very long logs are truncated in the viewer to the most recent lines — download the file to read the whole thing.
</Note>
